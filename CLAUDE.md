# NBlood hybrid core for MiSTer (Blood, Redneck Rampage, PowerSlave)

@hybrid/CLAUDE.md

## This core

- The engine's name is `NBloodD` (Danik, 2026-10-27): the core's `CONF_STR` name, set names `NBloodD_<id>`, folders `games/dnk/NBloodD/` and `logs/dnk/NBloodD/`, `_Other/dnk/dnk-NBloodD_*.rbf`, release `NBloodD_YYYYMMDD.zip`. Not `NBlood`, because MiSTer Frontier has a core called NBlood: its installer puts `[NBlood] main=Mister_NBlood` in `MiSTer.ini`, so loading any core named NBlood replaced Main_MiSTer with Frontier's program, which dropped our set name (every menu entry showed the list) and ran Frontier's Blood next to ours (found on Danik's MiSTer, 2026-10-27). The launcher, tty2oled+, dnkLauncher and the diagnostic report find the folders by the core's name, so they follow it. What stays `NBlood`: the repository, `core/NBlood.*` (Quartus), the chooser binary `NBlood` (`src/nblood.c`); `nblood` the game submodule, `nblood-bin`, log and lock. The games and their menu entries (`_Other/dnk-<title>.mgl`): `package/games.txt` (in the zip as `games/dnk/NBloodD/games.txt`, from which the database's build makes the launcher's catalogue).
- The game is the `nblood/` submodule, branch `mister`. Its MiSTer code is behind the `MISTER_HYBRID` build option.
- Build: `./build.sh` (game), `./core/build_core.sh` (FPGA), `./package.sh` (zip in `dist/`), `MISTER=root@<address> tools/deploy.sh`.
- Release: the zip in `releases/`. Players get it once it is published to the database, only when Danik asks: `hybrid/launcher/distribution.py publish ~/dnk_Distribution_MiSTer releases/NBloodD_YYYYMMDD.zip` (the rule in `hybrid/CLAUDE.md`).
- Try a build on the MiSTer without installing it: `MISTER=root@<address> tools/test_on_mister.sh <id>|list|nodata|log|stop` (the rule in `hybrid/CLAUDE.md`).
- Lines marked `GAME:` in the scripts and `TODO` in the READMEs are the places the template left for this game.

## NBlood

- The game is [NBlood](https://github.com/NBlood/NBlood) (`nblood/`, upstream master 497385d of 2026-09-14). No fork on GitHub yet (Danik, 2026-10-27): the submodule's URL is upstream's and `mister` is a local branch; `ItsDanik/NBlood` is made, and `.gitmodules` pointed at it, when the port is ready to publish. Launcher version 10 (hybrid `3f65c54`, committed but not pushed) starts a port only on its own `.rbf`, made because MiSTer Frontier's NBlood core is named `NBlood` too; since the core is `NBloodD` this port no longer needs it (Frontier's core finds no `games/dnk/NBlood/`, also with launcher 9).
- Games (Danik, 2026-10-27): BLOOD, CP (Cryptic Passage), RR, RRRA (Rides Again), EX (PowerSlave). Not here: Duke Nukem 3D and its add-ons (the EDuke32 core), Duke Nukem 64, NAM / NAPALM, WWII GI, all of which Rednukem runs too.
- Three programs on one engine: `nblood`, `rednukem`, `pcexhumed` (`make blood rr exhumed`, EDuke32's makefiles, `MISTER_HYBRID=1`). `NBlood` (`src/nblood.c`) is what the launcher starts, as DXXRebirth's chooser: it picks the game with `MH_PickGame()` and execs the program in the game's folder. The engine's MiSTer code (`source/build`, `source/audiolib`, `Common.mak`, `GNUmakefile`) is the EDuke32 core's (`~/MiSTer-duke3d/eduke32`, ec5824db8..1a7691472), which applied to NBlood without a conflict (2026-10-27): NBlood's engine is EDuke32's of nearly the same date.
- Data, in `games/dnk/NBloodD/` (DATADIR): `Blood/` (Cryptic Passage in it, as its release and Blood's GOG and Steam versions have it: `-ini CRYPTIC.INI`), `Redneck/` (both games; Danik's has `REDNECK.GRP` and `RA.GRP`: the chooser knows each by its size, the one rednukem knows, and names it in `DUKE3DGRP`, which rednukem reads before its settings), `PowerSlave/` (`STUFF.DAT` holds the art: no `TILES*.ART`). One folder per program, because their settings files and saved games have the same names. Redneck Rampage and Rides Again run in `Redneck/RR/` and `Redneck/RRRA/` (made by the chooser), with `Redneck/` as a search path, so that each has its own settings and saved games.
- Command line: `-usecwd` (else each program moves to `~/.config/<program>`) and `-j` the chooser's folder (GAMEDIR) for `nblood.pk3` / `pcexhumed.pk3`. Absolute paths: the engine's search paths drop a leading `../` (`Bcorrectfilename`), and Blood's command line takes a word starting with `/` for a switch except after `=` (`blood/src/getopt.cpp`), so Blood gets `-j=<path>`, the others `-j <path>`.
- Test data on the PC: `build/data/` (Blood, Redneck, PowerSlave from Danik's `~/Downloads/{NBlood,NRedneck,Exhumed}.7z`; never committed). `build/test/run.sh <id>` runs a game through the chooser against fakecore and saves three shots (`MISTER_HYBRID_CORE=NBloodD` is needed with `MISTER_HYBRID_SET`, as the launch script sets both).
- `nblood-bin`: the program `nblood` is called `nblood-bin` in `build/` and the zip (`build.sh`, `src/nblood.c` RUN, `package.sh`), because the SD card (exFAT) does not tell `nblood` from `NBlood`, nor `blood` from the data folder `Blood/` next to it (the first name, `blood`, was replaced by the data folder when Blood's data was copied over it on the MiSTer, 2026-10-27).
- Shared MiSTer code of the three programs: `source/build/src/mister.cpp` (`mister.h`): the option and trigger bits, `misterInit()` (exit codes 42 / 43 / 0), the screen size, the menu mask (bit 1 Blood, 2 Redneck, 3 PowerSlave; the `CONF_STR` hides each program's lines with `h`/`H`), the HUD moves, rumble, stick sensitivity (the OSD's 100%, Danik 2026-10-27: the left stick 2.5 times the game's own everywhere; the right stick 1.25 times in Rednukem and PowerSlave, 4.25 times in Blood, which turns 3.4 times slower at the same setting: both 1200 units of 2048 a second at full tilt, measured on the PC with the player's angle logged while fakecore held `analog 0 0 127 0`) and limit look. Each program has its own `mister_port.[ch]` (`source/{blood,rr,exhumed}/src/`): resolution, cheats, sticks.
- 2D art at 240 lines: the engine draws it one line a row, the 200 rows in the middle (`dorotspr_mister()`, engine.cpp) and moved by `rotatesprite_mister_yofs` (`MISTER_HUD()`). Code that works out its own screen coordinates for it must do the same: PowerSlave's `printext()` cut each letter out of its font with a clip rectangle of the stock mapping (16:10, 384 columns at 320x200) and showed the wrong glyphs at every size; its helpers in `enginesubs.cpp` follow the MiSTer mapping now. PowerSlave's health and magic pools move their fill sprite down by the level, off a 200-line screen: at 240 lines with a margin it showed below the bar, so the bar is drawn with a clip window ending at its bottom (`status.cpp`, the window keeping its middle, from which the art is placed).
- PowerSlave's menus read the keyboard alone: in its menus A is Return, B Escape and the d-pad the arrows, Start always Escape; Return and Escape also go into the typed characters (`keyBufferInsert()`), flushed on release (`exhumed/src/mister_port.cpp`). A new game asks for a name: empty, it is `GAME <n>` (`menu.cpp`). It counts as playing while the game loop ran in the last quarter second (`MiSTer_Playing()`); cheats and triggers wait for it. No rumble in PowerSlave: its *Rumble* line is hidden (`H3`).
- Upstream renderer hole (2026-10-27, not ours): at the start of Cryptic Passage's CP02 (Old Opera House) the near floor is not drawn in the classic renderer and the loading screen stays below the horizon. Same with the room-over-room code from before NBlood's rewrite (fbc5e1186, fe53066e0 reverted in a test build), and every engine change of ours is ARM-only, so the PC build renders as upstream.
- `package/screens/<id>.png` (2026-10-27): taken on the PC with `build/test/shot.sh <id> <wait> <fields> <args>` (the program started directly against fakecore at 320x200, `MISTER_HYBRID_FPS=0`, walked forward with the d-pad, a shot every 10 fields; `TAG=` names a run; one run at a time, parallel runs mixed their frames up) and `build/test/sheet.py`. BLOOD `-map E4M1.MAP -skill 2` frame 100 (a cultist), CP `-ini CRYPTIC.INI -map CP01.MAP` frame 150, RR `-v1 -l1 -s2` frame 50 (a chicken), RRRA `-v1 -l2 -s2` frame 10 (the motorcycle), EX `-2` frame 90 (an oasis). Blood's `-map` runs a level as a user map: wait 1100 fields for it.
- Sticks past 32767 (2026-10-27): Rednukem's look up / down and PowerSlave's turning and looking did `fix16_from_int(info.dpitch) / analogExtent`, which wraps above 32767: a stick at full tilt with the sensitivity above about 190% turned the other way. They do it in 64 bits now (`rr/src/player.cpp`, `exhumed/src/player.cpp`). Blood (`fix16_from_float`) never had it.
- Blood showing Cryptic Passage's title screen: the data, not the port. Cryptic Passage's DOS installer writes its art over `TILES007.ART` and `TILES015.ART` (Danik's, dated as `CRYPTIC.INI`); Blood needs its own two back, and Cryptic Passage then takes its art from `CPART07.AR_` / `CPART15.AR_`, as GOG and Steam ship them.
- Blood's menus took a controller button only when it was the one held (`switch (joy)` in `gamemenu.cpp`): Menu OK on the button of Fire set A and the right shoulder together and nothing happened, unless one bit came a frame before the other (Danik: OK / Back needed several presses, 2026-10-27). With `MISTER_HYBRID` a button counts when it goes down, Menu OK and Menu Back first, and the shoulders do nothing in the menus. Start opens the menu only alone still (`blood.cpp`, `demo.cpp`), as upstream.
